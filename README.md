# حسابداری نوین — برنامه حسابداری کسب‌وکار کوچک (ویندوز)

امکانات: **مشتریان و تامین‌کنندگان** • **کالاها و انبار** • **صدور فاکتور** • **دریافت و پرداخت** • **چک‌ها** • **گزارشات** • **کاربران و سطح دسترسی**
فناوری: Python + PySide6 + SQLite — رابط فارسیِ راست‌چین با تاریخ شمسی.

## ۱) اجرا

```bat
pip install -r requirements.txt
python seed_demo.py      :: اختیاری — ایجاد دادهٔ نمونه در demo.db جداگانه
python main.py
```

در اولین اجرا یک «مدیر سیستم» می‌سازید؛ از اجرای بعد ورود با رمز عبور الزامی است.

## ۲) تست‌ها

```bat
python tests/test_logic.py        :: ۳۶ تست منطق حسابداری
python tests/test_features.py     :: ۴۴ تست کاربران، چک‌ها، سنوات بدهی، قفل دوره، پشتیبان
python tests/test_ui.py           :: ۱۶ تست رابط کاربری (نیاز به QT_QPA_PLATFORM=offscreen در لینوکس)
python -m pytest                  :: ۱۰ رگرسیون امنیتی/حسابداری/مهاجرت
```

## ۳) ساخت فایل اجرایی (EXE)

**روشِ پیشنهادی** (از مشکلاتِ cmd در امان است):

```bat
python build_exe.py
```

**روشِ دوم** — دابل‌کلیک روی `build_windows.bat` (فقط نصب می‌کند و کار را به بالا می‌سپارد).

گزینه‌ها:

| فرمان | نتیجه |
|---|---|
| `python build_exe.py` | پوشهٔ `dist\Hesabdar\` — سریع و مطمئن |
| `python build_exe.py --onefile` | یک فایل exe یکپارچه (اجرای اول کمی کندتر) |
| `python build_exe.py --console` | همراه پنجرهٔ سیاهِ کنسول (برای دیدنِ خطاها) |
| `python build_exe.py --dry-run` | فقط نمایشِ فرمان، بدون نصب و ساخت |

خروجی: `dist\Hesabdar\Hesabdar.exe`

### اگر ساخت با خطا مواجه شد

| پیام | علت و رفع |
|---|---|
| `'python' is not recognized...` | پایتون نصب نیست یا به PATH اضافه نشده. هنگام نصب تیک **Add Python to PATH** را بزنید. |
| `'pyinstaller' is not recognized...` | از `python -m PyInstaller` استفاده کنید (اسکریپت‌ها همین کار را می‌کنند). |
| `ERROR: Script file 'main.py' does not exist` | اسکریپت را از پوشهٔ پروژه اجرا کنید. `build_windows.bat` خودش به پوشه‌اش می‌رود. |
| `Access is denied` هنگام نصب | پنجره را **Run as administrator** باز کنید، یا با `--user` نصب کنید. |
| `could not create '...': Permission denied` | پوشهٔ `dist` یا `build` در اکسپلورر باز است؛ ببندید و دوباره اجرا کنید. |
| exe اجرا می‌شود و فوراً بسته می‌شود | با `--console` بسازید و خطا را بخوانید؛ معمولاً فایل `schema.sql` یا پلاگینِ Qt گم شده. |
| `This application failed to start because no Qt platform plugin...` | `python -m pip install --force-reinstall PySide6` سپس دوباره بسازید. |
| آنتی‌ویروس exe را قرنطینه می‌کند | خطایِ شناخته‌شدهٔ بسته‌های PyInstaller است؛ برنامه را در فهرستِ سفید بگذارید. |

> نکتهٔ فنی: `build_windows.bat` عمداً فقط متنِ انگلیسی (ASCII) و سرِ خط‌های CRLF دارد،
> چون `cmd.exe` در ویندوز متنِ فارسیِ UTF-8 و خطوطِ LF را خراب می‌کند.

### متغیرهای محیطی (اختیاری)

| متغیر | کاربرد |
|---|---|
| `ACC_DB_PATH` | مسیرِ کاملِ فایل پایگاه داده (برای تست یا چند شرکت) |
| `ACC_DATA_DIR` | پوشهٔ داده و پشتیبان‌ها (نسخهٔ پرتابل: ذخیره در کنار برنامه) |

پیش‌فرضِ ویندوز: `%APPDATA%\SmallBizAccounting`

## ۵) قوانین حسابداریِ پیاده‌سازی‌شده

1. هر سند باید تراز باشد (اجرا در سطح پایگاه داده با تریگر).
2. سند قطعی‌شده هرگز ویرایش/حذف نمی‌شود؛ اصلاح فقط با سند معکوس.
3. مبالغ فقط عدد صحیح (ریال) — استفاده از float ممنوع.
4. تاریخ‌ها در پایگاه داده میلادی ذخیره می‌شوند و فقط برای نمایش شمسی می‌گردند.
5. موجودی انبار از مجموع حرکت‌ها محاسبه می‌شود، نه یک عدد جداگانه.
6. هر عملیات مالی به‌طور خودکار سند حسابداریِ تراز تولید می‌کند.
7. ثبت سند در دورهٔ (ماه) قفل‌شده ممنوع است.

## ۶) نقش‌های کاربری

| نقش | دسترسی‌ها |
|---|---|
| مدیر سیستم | همه‌چیز (از جمله مدیریت کاربران، قفل دوره، بازیابی پشتیبان) |
| حسابدار | ثبت/قطعی/ابطال فاکتور، دریافت و پرداخت، چک‌ها، کالا و اشخاص، گزارشات |
| اپراتور | فقط ثبتِ فاکتور و دریافت/پرداخت (بدون قطعی کردن و ابطال) |
| مشاهده‌گر | فقط مشاهدهٔ گزارشات |

> بدون ورود، هیچ دسترسی‌ای وجود ندارد. اسکریپت‌های نگهداری باید صریحاً از `auth.service_mode()` استفاده کنند.

## ۷) مهاجرت، پشتیبان و بازیابی

- در اولین اجرا با پایگاه داده قدیمی، برنامه به‌صورت خودکار **پشتیبان پیش از مهاجرت** می‌گیرد و سپس schema را به نسخه ۵ ارتقا می‌دهد.
- شماره فاکتورها در هر سال مالی جداست؛ اسناد قطعی هرگز ویرایش نمی‌شوند و اصلاح فقط با سند معکوس انجام می‌شود.
- پشتیبان‌گیری با `VACUUM INTO` و `integrity_check` انجام می‌شود.
- بازیابی از تنظیمات، فایل را اعتبارسنجی و مرحله‌بندی می‌کند؛ اعمال واقعی در **اجرای بعدی** و پس از گرفتن پشتیبان ایمنی از وضعیت فعلی انجام می‌شود.
- گزارش «کنترل سازگاری انبار و دفاتر» و «گزارش رویدادها» برای پایش سلامت داده‌ها اضافه شده‌اند.

## ۸) رابط کاربری جدید

- ناوبری کناری، کارت‌های شاخص، نمودار فروش ماهانه و هشدارهای داشبورد.
- حالت روشن/تیره و فونت فارسی وزیرمتن به‌صورت تعبیه‌شده.
- خروجی CSV ایمن‌شده در برابر فرمول‌های اکسل؛ چاپ/PDF با امکان لغو صحیح.

## ۹) پروفایل کسب‌وکار و اتصال ووکامرس

- در اولین راه‌اندازی، یکی از ۲۰ پروفایل فعالیت (از سوپرمارکت تا تولیدی و فروشگاه اینترنتی) انتخاب می‌شود. پروفایل‌ها KPI، واحد و موجودی پیش‌فرض و فیلدهای اختصاصی کالا را تنظیم می‌کنند؛ انتخاب قابل تغییر است.
- فیلدهای پروفایل کالا در `items.metadata_json` نگه‌داری می‌شوند. نرخ VAT از پروفایل حدس زده نمی‌شود و باید توسط مدیر طبق مقررات جاری تنظیم شود.
- اتصال WooCommerce در تنظیمات برنامه: REST API نسخه `wc/v3` روی HTTPS، sync دوره‌ای (پیش‌فرض ۲۰ ثانیه)، صف خروجی و Webhook اختیاری با HMAC. کالا/قیمت/SKU، موجودی ledger-owned، مشتری و سفارش‌های آنلاین واردشده پشتیبانی می‌شوند.
- سفارش پردازش/تکمیل‌شده به فاکتور دوبلری و رسید تبدیل می‌شود. سفارش لغو/Refund یا تغییر مبلغِ فاکتور قطعی، خودکار معکوس نمی‌شود و باید دستی بازبینی شود.
- **موجودی حسابداری مرجع است.** قبل از فعال‌کردن import سفارش، موجودی افتتاحیه و بهای کالا را ثبت کنید. کد کالا را با SKU ووکامرس برابر بگذارید.
- webhook فقط زمانی بلادرنگ‌تر است که فروشگاه URL عمومی HTTPS را به `/woo/webhook` برنامه route کند؛ برای دسکتاپ پشت NAT، reverse proxy/TLS و فایروال امن لازم است. بدون آن polling نزدیک‌به‌لحظه برقرار است.
- اتصال با فروشگاه واقعی در این محیط E2E نشده؛ پیش از بهره‌برداری مالی در staging ووکامرس، واحد پول، VAT، shipping، gateway و سفارش نمونه را کنترل کنید.
- جدول کاملِ امکانات پیوست و محدودیت‌ها: [`docs/BUSINESS-PROFILES-WOOCOMMERCE.md`](docs/BUSINESS-PROFILES-WOOCOMMERCE.md).
